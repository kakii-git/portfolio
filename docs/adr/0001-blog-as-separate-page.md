# 記事一覧を /works から独立ページ /blog へ切り出す

`/works` は「制作物」と「記事」（Qiita のフィード集約）が同居するページだった。自サイトで本文まで持つ記事（自サイト記事）を追加するにあたり、記事は `/blog` という独立ページへ移し、`/works` は制作物のみのページにする。理由は、外部記事と自サイト記事を1本のリストに統合して「ka.kii が書いたものを読む場所」を1箇所に定めるため、および `/works` のページ名と中身のズレを解消するため。

## 検討した代替案

- **`/works#writing` を残したまま `/blog` も作る**: 同じ記事一覧が2つの URL に出るため、重複コンテンツとして canonical の指定が必要になり、読者にとってもどちらを見るべきか分からなくなる。
- **`/works` 内に自サイト記事も統合し、一覧ページを新設しない**: 変更は最小で済むが、記事が増えるほど `/works` が制作物の一覧として機能しなくなる。

## 影響

- アンカー `/works#writing` は失われる。外部からの参照・内部リンクともに存在せず（sitemap はページ単位で出力される）、リダイレクトは設けない。
- サイトが Home / Works / Blog の3ページ構成になり、`Header.astro` の `siteNav`（ハードコード）への追加が必要になる。
